  深色模式改动量分析报告

  📊 整体评估

  改动量：中等偏大

  - 样式文件数量：13 个 CSS 文件
  - 颜色相关属性：约 330 处
  - 硬编码颜色值：约 260 处
  - 预计工作量：4-6 小时

  🎨 需要适配的主要区域

  1. 基础色彩系统（必改）

  - 背景色：#f7f7f7 → 深色背景
  - 文字色：#333, #666, #999 → 浅色文字
  - 边框色：#e0e0e0, #e5e5e5 → 深色边框
  - 白色元素：white, #fff → 深色卡片

  2. 卡片系统（重点）

  - 普通卡片：#fafafa → 深色卡片
  - 置顶卡片：淡蓝色渐变 → 深蓝色渐变
  - 收藏卡片：淡金色渐变 → 深金色渐变
  - 混合卡片：淡紫色渐变 → 深紫色渐变
  - hover 效果需要重新调整

  3. 工具栏（中等）

  - 按钮背景：白色 → 深色
  - 按钮边框：浅灰 → 深灰
  - 渐变色按钮（置顶、收藏、AI、OCR）需要调整对比度
  - 分隔符颜色需要调整

  4. 搜索栏和筛选（中等）

  - 输入框背景：白色 → 深色
  - 类型筛选按钮：#f5f5f5 → 深色
  - 收藏按钮：白色 → 深色
  - 设置按钮：白色 → 深色

  5. 标签系统（较少）

  - 标签本身是彩色的，对比度已经够高
  - 只需调整：
    - 添加标签按钮背景
    - 标签下拉框背景和边框
    - 输入框背景

  6. 备注系统（较少）

  - 备注显示文字颜色
  - 备注编辑框背景和边框
  - 保存/取消按钮（已有渐变色，可能不需要改）

  7. 标题栏（较少）

  - 背景：白色 → 深色
  - 文字：#666 → 浅色
  - 按钮 hover 效果需要调整

  8. 设置面板（中等）

  - 背景：白色 → 深色
  - 输入框：白色 → 深色
  - 按钮：需要调整
  - 标签页：需要调整

  9. 滚动条（较少）

  - 滚动条颜色需要调整

  10. 阴影效果（全局）

  - 所有 box-shadow 需要调整
  - 浅色阴影 → 深色阴影或更强的对比

  💡 实现方案建议

  方案 A：CSS 变量 + 类切换（推荐）

  优点：
  - 维护性好，一处定义，全局生效
  - 性能好，浏览器原生支持
  - 易于扩展（未来可能支持更多主题）

  实现步骤：
  1. 定义 CSS 变量（约 30-40 个变量）
  2. 替换所有硬编码颜色为变量（260 处）
  3. 添加 .dark-mode 类的变量覆盖
  4. 前端添加主题切换逻辑
  5. 后端保存主题配置

  预计工作量： 4-5 小时

  方案 B：双份 CSS 文件

  优点：
  - 改动相对独立，不影响现有代码

  缺点：
  - 维护成本高（每次改样式要改两份）
  - 文件体积增加
  - 不推荐

  ## UI 设计原则

  ### 多语言兼容
  **所有 UI 设计必须同时兼顾中文和英文场景：**
  - 按钮和标签宽度需要考虑英文较长的情况
  - 文本截断和换行要在两种语言下都美观
  - 字体选择要同时支持中英文显示

  ### 深色模式支持
  **所有 UI 组件必须支持深色模式：**
  - 使用 CSS 变量定义颜色，不要硬编码
  - 确保深色模式下的对比度符合 WCAG AA 标准
  - 渐变色和阴影效果需要在两种模式下都美观
  - 图片和图标需要考虑深色背景下的可见性

  ⚖️ 我的建议

  建议推进，理由：

  1. 改动量可控：虽然有 260 处颜色值，但使用 CSS 变量后，实际只需定义 30-40 个变量，然后批量替换
  2. 符合产品定位："审美优先"是你的核心理念之一，深色模式是现代应用的标配
  3. 用户需求：很多用户习惯在夜间使用深色模式，减少眼睛疲劳
  4. 技术成熟：CSS 变量 + 系统主题检测是成熟方案，风险低
  5. 一次性投入：现在做好基础架构，后续维护成本很低

  实施建议：
  - 先做 CSS 变量重构（2-3 小时）
  - 再设计深色配色方案（1-2 小时）
  - 最后添加切换逻辑和配置（1 小时）
