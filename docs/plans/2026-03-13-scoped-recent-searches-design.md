# 分作用域最近搜索设计

日期：2026-03-13

## 背景

最近搜索下拉已经在历史流顶部搜索框落地，但后续确认发现三类搜索入口的语义并不相同：

1. 历史流搜索用于全量历史记录回查。
2. 收藏区搜索用于收藏流内部检索。
3. 工作区搜索用于工作区内部检索。

如果三者共用同一套搜索词与最近搜索历史，会产生明显的语义串味。

## 决策

### 数据边界

- 历史流使用独立的 `searchQuery + historyRecentSearches`
- 收藏区使用独立的 `collectionSearchQuery + collectionRecentSearches`
- 工作区使用独立的 `workbenchSearchQuery + workbenchRecentSearches`

### 存储方式

- 最近搜索不进入 SQLite 主数据库。
- 最近搜索只保存在本地配置存储（`localStorage`）。
- 每个作用域独立 key，彼此不互相污染。

### 最近搜索规则

- 每组最多保留 10 条。
- 字符串 trim 后去重。
- 重复搜索会移动到最前。
- 支持单条删除与整组清空。

## 交互规则

三处搜索入口统一采用以下交互：

1. 仅在精准点击搜索输入框时展开最近搜索。
2. 输入框为空且下拉已展开时，再点一次输入框会收起。
3. 点顶部栏、窗口激活、其他非输入框区域不会误触发展开。
4. `ArrowDown / ArrowUp / Enter / Escape` 可用于键盘操作最近搜索下拉。

## 为什么不放数据库

- 最近搜索属于本机 UI 记忆，不是业务主数据。
- 不需要参与后端筛选、同步、迁移和备份语义。
- 放数据库会增加 schema、命令和维护复杂度，收益很低。

## 验收点

1. 历史流、收藏区、工作区三处最近搜索互不串词。
2. 收藏区搜索不会写入历史流最近搜索。
3. 工作区搜索不会写入历史流或收藏区最近搜索。
4. 重启应用后各自最近搜索仍然保留。
