# Collector AI 标签批量上传设计

日期：2026-08-22
范围：将 Collector 上传收敛为固定批处理，并携带本地 AI 标签
状态：Approved

## 1. 背景

Collector 当前在新文本或链接条目写入后立即异步上传，同时另有本地 AI 标签生成任务。两条任务互不等待，导致分析平台通常只能收到正文，无法利用已经配置的 AI 标签。

Collector 的职责继续保持为“接收并归档”，不引入服务端 AI、数据库或待处理队列。

## 2. 方案

1. 删除新条目落库后的即时 Collector 上传分支。
2. 保留客户端已有的最近 24 小时未上传扫描与上传标记机制。
3. 后台同步固定每 5 分钟执行一次，首次同步也在完整周期后执行；用户点击“立即同步”仍立即运行相同批处理。
4. 上传前从数据库读取条目当前状态，将 `AI:` 前缀的标签转换为 `ai_tags` 字段随正文上传。
5. 到达批处理时间时，无论 AI 标签是否已生成，条目都上传并标记成功；不等待、不补发、不维护逐条状态机。
6. 用户手动标签不上传，避免把个人分类习惯作为分析数据发送。

## 3. 数据契约

客户端新增可选 JSON 字段：

```json
{
  "ai_tags": ["代码", "Rust"]
}
```

Collector 将该字段原样归档到 JSONL 事件中。没有 AI 标签时省略字段，保持与旧客户端和旧分析脚本兼容。

## 4. 非目标

1. 不增加服务端 AI 调用。
2. 不上传用户手动标签、OCR 文本、AI 标题或代码语言。
3. 不建立“AI 完成状态”、超时状态或标签补发机制。
4. 不修改 Collector 的保留、限流、鉴权和文本截断策略。

## 5. 验收标准

1. 新条目不会在写入后立即触发 Collector HTTP 上传。
2. 未上传条目在下一个 5 分钟批次或用户手动同步时发送。
3. AI 标签在批次前已生成时，归档 JSONL 包含 `ai_tags`；手动标签不包含在其中。
4. 未生成 AI 标签的条目仍可正常上传，且 `ai_tags` 被省略。
5. Collector 继续兼容没有 `ai_tags` 的客户端请求。
6. Rust 与 Go 测试和构建通过。
