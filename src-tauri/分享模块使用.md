这份 PRD 旨在为你梳理**“智能分享与二维码生成”**功能的完整逻辑。

核心策略采用 “分级处理”：小文本走本地，大文本/图片走云端。
关于你提到的“默认免费/无 Key”方案，我选定 File.io 作为默认服务。它不需要注册，不需要 API Key，且支持“阅后即焚”（下载一次即销毁），完美契合剪贴板的中转场景。

PRD：ClipBox 智能分享模块 (Smart Sharing)
1. 需求背景
用户需要将电脑端的剪贴板内容（文本/代码/图片）快速流转到手机或其他移动设备，但不希望通过登录微信/QQ 等臃肿软件传输，也不希望搭建复杂的局域网服务。

3. 功能详细说明
3.1 分享入口
入口位置：

列表项右键菜单 -> “分享 / 二维码”。

(可选) 详情页顶部常驻“分享”图标。

快捷键：选中条目后按 Ctrl + Shift + S (建议)。

3.2 策略一：本地纯文本分享 (Local QR)
触发条件：内容为文本 且 长度 < 1500 字符。

逻辑：

直接将文本编码为 QR Code。

不进行任何网络请求。

容错：如果文本包含特殊字符导致编码失败，自动降级到“云端上传流程”。

3.3 策略二：默认云端分享 (Default Free Tier)
触发条件：(文本 > 1500 字符 OR 图片) 且 (用户未配置 S3)。

服务商：File.io (或者 transfer.sh)。

实现逻辑：

API：POST https://file.io/

参数：expires: 1d (1天过期), autoDelete: true (下载一次后自动删除)。

无需鉴权：直接调用，不需要 API Key。

隐私说明：在 UI 上标注“使用 File.io 临时中转，阅后即焚”。

返回：获取 JSON 中的 link 字段。

3.4 策略三：自定义云端分享 (BYOS - S3)
触发条件：用户在设置中配置了 S3 信息。

支持协议：AWS S3 通用协议 (支持阿里云 OSS、腾讯云 COS、MinIO、Cloudflare R2)。

实现逻辑：

使用 rust-s3 库上传。

文件路径建议：/clipbox/share/{uuid}.{ext}。

生成预签名链接 (Presigned URL) 或 公开访问链接（视 Bucket 权限而定，建议默认用公开链接）。

Rust
use serde::{Deserialize, Serialize};

#[derive(Serialize)]
struct ShareResult {
    qr_data: String, // Base64 编码的二维码图片
    url: Option<String>, // 如果是云端模式，返回 URL
    mode: String, // "local", "file.io", "s3"
}

// 默认上传到 File.io (无需 Key)
async fn upload_to_fileio(file_path: String) -> Result<String, String> {
    let client = reqwest::Client::new();
    // File.io 接口极其简单
    let form = reqwest::multipart::Form::new()
        .file("file", &file_path).await.map_err(|e| e.to_string())?;
    
    let res = client.post("https://file.io/?expires=1d")
        .multipart(form)
        .send()
        .await.map_err(|e| e.to_string())?;

    if res.status().is_success() {
        let json: serde_json::Value = res.json().await.map_err(|e| e.to_string())?;
        // 返回 link 字段
        Ok(json["link"].as_str().unwrap_or("").to_string())
    } else {
        Err("File.io upload failed".to_string())
    }
}

#[tauri::command]
async fn generate_share_qr(
    content_type: String, // "text" or "image"
    content_data: String, // 文本内容 或 图片路径
    use_s3: bool,
    s3_config: Option<S3Config>
) -> Result<ShareResult, String> {
    
    let mut target_url = String::new();
    let mut share_mode = "local".to_string();

    // 1. 决策逻辑
    if content_type == "text" && content_data.len() < 1500 {
        // 走本地 QR
        target_url = content_data;
    } else {
        // 走云端上传
        if use_s3 && s3_config.is_some() {
            share_mode = "s3".to_string();
            target_url = upload_to_s3(content_data, s3_config.unwrap()).await?;
        } else {
            share_mode = "file.io".to_string();
            // 如果是文本，先存临时文件再上传；如果是图片路径直接传
            let file_path = ensure_file(content_data); 
            target_url = upload_to_fileio(file_path).await?;
        }
    }

    // 2. 生成二维码图片 (Base64)
    let code = qrcode::QrCode::new(target_url.as_bytes()).unwrap();
    let image = code.render::<image::Luma<u8>>().build();
    // 转 Base64 返回给前端展示...
    
    Ok(ShareResult { qr_data: base64_image, url: Some(target_url), mode: share_mode })
}
6. 异常处理与兜底 (Edge Cases)
网络不通 (File.io 连不上)：

现象：生成二维码时一直在转圈，最后报错。

处理：弹窗提示“云端服务连接失败，请检查网络或配置”。如果内容是文本，提供“强制生成文本二维码（可能无法识别）”的按钮作为逃生通道。

File.io 每日限额：

File.io 免费版其实有速率限制。

处理：如果 API 返回 429 (Too Many Requests)，提示用户“免费分享次数已耗尽，请稍后再试或配置 S3”。

敏感词屏蔽：

虽然 File.io 是国外的，但国内网络偶尔会阻断其域名。

处理：这是不可抗力。在设置页加一行小字建议：“国内网络环境下，建议配置阿里云 OSS 以获得最佳稳定性。”

7. 总结
这套方案完美的平衡了你的需求：

轻量：默认情况（文本）完全本地。

零成本：大文件走 File.io，不用你掏服务器费，也不用用户掏钱。

高阶：支持 S3 配置，满足极客对稳定性和隐私的极致追求。

你只需要实现前端一个弹窗，后端两个上传函数（File.io + S3），这个功能就算完美交付了。
