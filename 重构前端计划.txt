ClipBox 产品需求文档 (PRD) - 双栏工作台版 v1.0
1. 产品概述 (Overview)
产品定位： 极简、高效的生产力剪贴板工具。
核心理念： “左侧是无限的时间流，右侧是专注的工作台。”
设计风格： 类 Flomo 风格 强调高信息密度与无干扰的交互体验。

2. 界面布局 (UI Layout)
界面采用严格的 双栏布局 (Dual-Column Layout)，暂时不支持单栏切换（我还没想好）。

左栏 (35% 宽度)：历史流 (The Stream)

用于展示所有历史剪贴板记录。

视觉：紧凑列表，无限滚动，无过多装饰 其实就是剪切流。

右栏 (65% 宽度)：多态面板 (The Polymorphic Panel)

这是用户的核心操作区，根据上下文在“搜集箱”与“预览页”之间切换。

视觉：宽敞、沉浸，支持富文本渲染与多卡片堆叠。

3. 核心功能模块 (Functional Modules)
3.1 左栏：历史流 (History Stream)
内容展示：

卡片高度固定（约 2-3 行），超长文本截断。整体是卡片风格。


显示内容摘要、类型图标（文本/图片/代码） 和标签。

交互动作：

悬停一段时间： 触发右栏进入 [预览模式]。此时之前的工具栏就可以完全显示出来了。

拖拽 (Drag)： 抓取卡片，触发右栏强制进入 [搜集模式]。

点击： 还是之前的复制。

视觉反馈：

被选中的卡片（在右侧预览中）保持区分度的颜色状态。

已被搜集（Pin）的卡片，在左侧显示之前我们约定的背景色（这个你知道），表示该项已在右侧存在。

3.2 右栏：多态面板 (The Panel)
右栏拥有两个互斥的视图状态。

状态 A：搜集箱/工作台 (Collection Workbench) —— [默认状态]
定义： 存放所有被用户“置顶”或“拖入”的内容。相当于一个临时的拼接板。

初始状态 (Empty State)：

当用户初次使用或清空搜集箱时，展示引导插画/文字。

文案示例： “从左侧拖拽，或点击 Pin 图标，将内容固定在这里。”

视觉： 极简的虚线框或淡绿色占位符，暗示此处可放置内容。

内容排列：

卡片以完整高度展示（支持代码高亮、长文本）。

支持卡片上下拖拽排序。

顶部功能区：

快速笔记 (Quick Note)： 一个常驻输入框。输入文字并回车后，自动生成一张新卡片并立即置顶在当前列表中（同时保存至左侧历史）。

底部操作栏：

合并复制： 将搜集箱内所有内容按顺序合并并复制到剪贴板。

一键清空 (Unpin All)： 点击后，所有卡片从右栏移除（非删除），触发“飞回左侧”的动画。

状态 B：预览页 (Preview Detail) —— [临时状态]
定义： 用于查看左侧某条记录的完整详情。

触发方式： 单击左侧历史流中的任意卡片。

展示内容：

该记录的完整大图（也不是完整 还是自适应的）、全量文字（也不是全量 是可以滚动了啦）、工具栏

顶部导航：

显示 “< 返回搜集箱” 按钮。

显示 “加入搜集 (Pin)” 按钮。

4. 关键交互逻辑与状态机 (Interaction Logic)
这是本产品的核心体验所在，必须严格执行。

4.1 拖拽即归位 (Drag to Reveal) —— [高优先级]
解决“预览”与“搜集”的空间冲突。

场景： 用户正在右栏查看某条记录的详情（处于 [预览模式]），此时他觉得这条记录很有用，想把它拖进搜集箱；或者他想把左侧另一条记录拖进搜集箱。

逻辑：

监听左侧列表的 OnDragStart 事件。

一旦监测到拖拽开始，无论右栏当前处于什么状态（哪怕是预览态），强制瞬间切换回 [搜集模式]。

视觉效果： 预览详情页像幕布一样退去（Fade Out/Slide Out），露出底下的搜集箱，用户直接将卡片拖入搜集箱的列表中。

目的： 确保用户永远不会因为“没地方拖”而感到困惑。

4.2 预览的退出机制 (Exit Preview)
点击“返回”按钮： 右栏切回 [搜集模式]。

点击左侧“空白处”： 取消左侧的选中状态，右栏切回 [搜集模式]。

点击“加入搜集”： 当前预览的内容自动进入搜集箱，右栏同时切换为 [搜集模式]，并滚动到该新卡片的位置。

4.3 数据流向与持久化 (Data Persistence)
搜集 = 置顶 (Pin)：

右栏中的所有内容，在数据库中均标记为 is_pinned = true。

左栏历史流中，对应的内容不消失，但显示 Pin 标记。

持久化：

用户关闭软件再打开，右栏 [搜集模式] 的内容必须原样保留。

[预览模式] 不保留，重启后默认回到搜集模式。

笔记逻辑：

在右栏新建的笔记，逻辑上等同于：“新建一条历史记录” + “自动执行 Pin 操作”。

5. 动画与反馈细节 (Micro-interactions)
清空动画 (The Fly-back)：

点击右栏底部的“清空”时，卡片不要直接消失。

应执行一个 向左位移 + 透明度降低 的动画，暗示它们“飞回”了左侧的历史仓库中。

提示语：“已归档至历史流”。

拖拽吸附 (Snap to Grid)：

当卡片被拖入右栏时，右栏现有的卡片应自动腾出空间（占位符动画），给予明确的放置反馈。

6. 异常边界情况 (Edge Cases)
Q: 如果搜集箱为空，拖拽进去会发生什么？

A: 搜集箱的 Empty State 消失，第一张卡片占据列表顶部。

Q: 如果在预览模式下，预览的内容本身就是“已搜集”的内容，显示什么？

A: 依然显示预览详情（为了查看大图或全代码），但顶部的操作按钮变为“移除搜集 (Unpin)”。

Q: 右栏笔记输入一半切走了怎么办？

A: 应当自动保存草稿，或者在切换回搜集模式时保留输入框内容。

开发总结 (To Developers)
View Layer: 右栏是一个单一的容器，根据 CurrentState (Enum: Collection, Preview) 渲染不同的组件。

State Management: 需要一个全局 Store 来管理 PinnedItems[] 和 PreviewItem。

Key Trigger: 左侧的 DragStart 事件具有最高优先级，它是一个强制的状态重置信号。

## 当前 Slint 实现分析（代码现状 vs PRD 设计）

### 一、整体架构现状

当前已用纯 Slint UI 实现了双栏布局的基本骨架，涉及以下文件：

| 文件 | 职责 | 行数 |
|------|------|------|
| `ui/main.slint` | 主窗口，双栏容器，状态属性 & 回调声明 | ~611 行 |
| `ui/components/history_stream.slint` | 左栏：搜索 + 筛选 + 紧凑卡片列表 | ~299 行 |
| `ui/components/collection_panel.slint` | 右栏状态A：搜集箱（快速笔记 + Pin列表 + 底部操作栏） | ~277 行 |
| `ui/components/preview_panel.slint` | 右栏状态B：预览页（返回/Pin按钮 + 内容编辑 + ItemCard） | ~239 行 |
| `ui/components/item_card.slint` | 卡片组件（compact 紧凑模式 + normal 完整模式） | ~641 行 |
| `src-tauri/src/main.rs` | Rust 绑定层，所有回调实现 | ~2200+ 行 |

### 二、已实现的功能（PRD 对照）

#### ✅ 已完成
1. **双栏布局** — `HorizontalLayout { HistoryStream(35%) | CollectionPanel/PreviewPanel(65%) }`
2. **左栏紧凑卡片** — `ItemCard` 的 `compact-mode: true`，显示缩略图/类型图标 + 内容摘要 + Pin/收藏标记 + 标签行
3. **右栏状态切换** — 通过 `right-panel-mode` ("collection" | "preview") + `preview-item-id` 条件渲染
4. **搜集箱空状态** — 虚线框 + Pin 图标 + 引导文案
5. **快速笔记** — 搜集箱顶部常驻输入框，回车提交
6. **底部操作栏** — 合并复制 + 一键清空（仅 Pin 列表非空时显示）
7. **预览页** — 返回搜集箱按钮 + Pin/Unpin 按钮 + 内容编辑（TextInput）+ 备注编辑 + 保存 + 完整 ItemCard
8. **左栏选中高亮** — `is-selected: root.preview-item-id == item.id`，选中卡片有 accent 边框
9. **Pin 卡片背景色区分** — `card-pinned-bg` / `card-pinned-hover` / `card-pin-fav-bg` 等主题色
10. **搜索 + 类型筛选 + 收藏筛选 + 标签筛选** — 完整实现
11. **悬停预览触发** — Rust 端有 `PREVIEW_SHOW_DELAY_MS: 340ms` 延迟逻辑（通过 hover-enter/hover-leave 回调）
12. **数据持久化** — `is_pinned` 数据库字段，重启后搜集箱内容保留

#### ❌ 未实现 / 受 Slint 限制无法实现
1. **拖拽 (Drag & Drop)** — PRD 核心交互。Slint 不支持列表项的自由拖拽，无法实现：
   - 左栏卡片拖入右栏搜集箱
   - 搜集箱内卡片拖拽排序
   - 拖拽开始时强制切回搜集模式（"拖拽即归位"）
2. **清空飞回动画** — PRD 要求卡片向左位移 + 透明度降低。Slint 的 `animate` 只支持属性插值，无法对 `for` 循环中的列表项做逐个退场动画
3. **拖拽吸附占位符** — 需要拖拽支持，同上
4. **富文本渲染 / 代码高亮** — Slint 的 `Text` 组件不支持富文本，无法做语法高亮
5. **无限滚动 / 懒加载** — Slint 的 `Flickable` + `for` 会一次性渲染所有项，没有虚拟滚动
6. **平滑的面板切换动画** — 搜集箱 ↔ 预览的切换是硬切（条件渲染），无法做 Fade/Slide 过渡

### 三、Slint 实现中的痛点

1. **回调透传地狱** — 每个 ItemCard 的 11 个回调（clicked, double-clicked, toggle-pin, toggle-favorite, toggle-expand, start-edit-note, generate-ai-tags, handle-ocr, open-item, start-add-tag, tag-clicked）需要从 ItemCard → CollectionPanel/PreviewPanel/HistoryStream → MainWindow → main.rs 逐层手动透传。新增一个回调要改 4-5 个文件。
2. **状态管理原始** — 所有状态都是 MainWindow 上的扁平属性（`right-panel-mode`, `preview-item-id`, `expanded-item-id`, `copied-item-id` 等），没有 Store/Context 概念，组件间通信全靠属性下传 + 回调上传。
3. **条件渲染 vs 动画冲突** — Slint 的 `if condition: Element {}` 是销毁/重建，无法在销毁前播放退出动画。这直接导致 PRD 中所有过渡动画无法实现。
4. **列表操作能力弱** — `for item in model` 不支持：拖拽排序、单项动画、虚拟滚动、动态插入动画。
5. **布局系统限制** — 没有 CSS Flexbox/Grid 那样灵活，对齐规则反直觉（见 CLAUDE.md 中的对齐规则说明）。
6. **main.rs 膨胀** — 所有回调绑定都在一个文件里，已超 2200 行，且每个回调都是 `main_window.on_xxx({ ... })` 的重复模式。

### 四、如果迁移到 Tauri (WebView) 的收益分析

| 维度 | Slint 现状 | Tauri + React/Vue 预期 |
|------|-----------|----------------------|
| 拖拽 | ❌ 不支持 | ✅ HTML5 Drag & Drop / react-dnd / dnd-kit |
| 动画 | 仅属性插值，无退场动画 | ✅ Framer Motion / CSS transitions / AnimatePresence |
| 富文本 | ❌ 纯文本 | ✅ 代码高亮(Prism/Shiki)、Markdown渲染 |
| 虚拟滚动 | ❌ 全量渲染 | ✅ react-virtuoso / tanstack-virtual |
| 状态管理 | 扁平属性 + 回调透传 | ✅ Zustand / Jotai / Redux，组件直接订阅 |
| 组件通信 | 逐层透传 | ✅ Context / Event Bus / 状态库直接访问 |
| 过渡动画 | 条件渲染=硬切 | ✅ AnimatePresence 退场动画 |
| 样式系统 | 内联属性，无变量复用 | ✅ Tailwind / CSS Variables / styled-components |
| 开发效率 | 改一个回调改5个文件 | 组件内闭合，改动局部化 |
| 生态 | 极小 | 极大（npm 生态） |

### 五、迁移建议

如果决定迁回 Tauri WebView，建议保留的部分：
- **Rust 后端逻辑**：`core/`, `platform/`, `repository/`, `ai/`, `ocr/`, `mcp/` 这些模块完全不用动
- **数据库 schema**：`clipboard_items`, `app_config` 表结构不变
- **数据模型**：`RawItemData`, `ClipboardManager` 等可以直接通过 Tauri IPC 暴露给前端

需要重写的部分：
- 整个 `ui/` 目录的 `.slint` 文件 → 替换为 React/Vue 组件
- `main.rs` 中的 Slint 绑定代码 → 替换为 Tauri `#[tauri::command]` 命令
- 前端状态管理重新设计

### 六、PRD 中尚未明确的设计点

1. 搜集箱卡片的排序规则（按 Pin 时间？按拖入顺序？支持手动排序？）
2. 合并复制的分隔符（换行？空行？自定义？）
3. 预览模式下编辑保存后，是否自动刷新左栏对应卡片
4. 最大 Pin 数量限制（当前有 `max-pinned-items` 配置，默认 3，是否合理？）
5. 快速笔记是否支持多行输入（当前是单行 TextInput）
